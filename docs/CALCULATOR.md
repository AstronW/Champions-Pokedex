# Champions 伤害计算器

入口：侧边栏“伤害计算”，或宝可梦详情底部“用于伤害计算”。界面按设计稿 v2：攻击方、招式、防守方、天气/场地/其他条件四张卡片，结果吸附在底部（横屏时位于右侧）；其余条件在“更多条件”中展开。界面使用原生 Compose，计算在后台线程运行；无需网络或网页服务。

## 计算与数据边界

- 复用邻目录 `damage-calc` 的 `calc/src`，固定提交 `eb9af6d94e7ee0ce034d2d6f2d44d4b2d66ff981`。副本在 `vendor/damage-calc/src`，源文件未修改。使用 `Generations.get(0)` 的 Champions 规则，固定 50 级、每项能力点 0–32；上游没有限制总能力点；界面滑杆按 Champions 规则限制每只合计 66 点，“更多条件”中的数字输入仍允许假设分配并显示总量。默认配置：攻击方按招式分类为固执/内敛、攻击或特攻 32 + 速度 32 + HP 2；防守方为淘气/温和、HP 32 + 对应防御 32 + 另一防御 2。
- 396 条形态通过明确规则与 `scripts/calculator/form-aliases.json` 映射。形态属性、种族值、体重取自 `dex.json`；特性限定为该形态的源数据。性别遵守源数据的固定性别。
- 335 个开放攻击招式可选。威力、分类、属性、优先度和接触标记使用图鉴字段；动态威力标记 1 保留计算内核规则。其余伤害相关标记和特殊效果取自上游。
- “拍击”存在于图鉴开放表，但缺少上游 Champions 记录。仅这一招显式取上游第九世代的通用招式元数据，仍在 Champions 内核计算，并使用图鉴数值。
- 道具范围采用上游 Champions 表的 166 项；中文名从与图鉴同指纹的 `champout/item.csv` 导入，并校验 manifest 哈希。不是从 Wiki 描述推测道具效果。
- 默认招式列表按当前形态学习关系过滤。“全部开放攻击招式”允许假设组合，并标出无法学习的招式。从列表选择新宝可梦重置该方配置；同一物种的形态切换保留能力调整（性格）、能力点、道具与条件，只更新特性与性别；交换保留双方配置并交换各方场地状态。
- 百变怪等没有开放攻击招式的形态可以正常进入和选择，显示无招式提示，不生成伤害结果。可手动开启全部招式后选择假设招式；关闭时恢复学习表约束，没有合法招式则清除结果。

可调项：能力调整（“提升 ×1.1”与“降低 ×0.9”两项独立选择；两项都选且不同时换算为对应性格名传给内核，否则按无修正计算并提示）、能力点、五项能力等级、特性及条件触发、道具、HP 百分比、异常状态、性别、倒下队友数、要害、合法多段命中次数、单双打、天气、场地、重力、奇妙/魔法空间、双方墙/守住/顺风/帮助及队友增益。

天气、场地在界面中明确指定，天气特性不会自动改写场地输入；威吓等入场能力修正遵循上游执行顺序。需要手动关闭或更换假设特性来模拟它未触发的情况。

## 结果含义

输出伤害范围、占最大 HP 的百分比、逐段随机伤害值，以及伤害达到当前 HP 的概率。单段按上游 16 个等概率随机值；多段逐段卷积，不能把每段第 i 个随机值直接相加后当作完整分布。

这些结果假定招式命中；不包含命中率、气势披带、挺住、回合末伤害/回复、换入钉子或完整回合模拟。连续使用招式的回合数固定为 1。概率是伤害阈值概率，不代表包含所有存活机制的击倒概率。上游已有规则和局限随该固定版本保留，未声明为 Champions 实机逐项校验结果。

## 实现和更新

性能：单次计算约 25 ms（模拟器），首次需解释约 900 KB 的内核脚本，模拟器 debug 版约 8 秒。应用在图鉴数据加载后于后台预热内核，计算器打开时通常已就绪；未就绪时结果区显示“正在准备计算内核”。输入防抖 60 ms。

`CalculatorEngine.kt` 使用 Rhino 1.7.15.1 解释模式，禁止 Java 类访问，只传 JSON 字符串。解释器串行访问；Compose 使用后台 dispatcher，参数变化后清除旧结果，取消旧任务回传。输入及列表状态通过现有 SaveableStateProvider 随栏目/返回栈条目保存。

`CalculatorData.kt` 集中默认配置、宝可梦/形态选择、学习表约束和双方交换规则，供界面及单元测试共用。`CalculatorCatalog` 将性格、道具及多段命中范围解析为只读元数据，在 ViewModel 内按需加载一次；控件复用选项列表，输入变化时不再重复解析整张表。图鉴的形态顺序、已开放招式和学习表索引由 `Dex` 统一建立，属性相性由 `TypeChart.kt` 提供，主题仅管理显示样式。内核使用的原始 JSON 合同不变。

`scripts/calculator/adapter.js` 负责图鉴适配、输入约束和结果格式；生成的 `engine.js`、`adapter.js`、`catalog.json` 不手改。`provenance.json` 记录上游提交、实际参与打包的逐文件源码哈希、图鉴/道具来源哈希及输出哈希。`build.ps1` 在构建前核对数据版本，避免更新图鉴后沿用旧映射。

```powershell
# 重建内核资源、映射、中文道具表和对照用例，再打包优化版
./build.ps1 -ImportCalculator
# 仅执行算法与覆盖检查（会刷新 Node 参考用例）
node scripts/calculator/test.cjs
# 在与 Android 相同的 Rhino 解释模式下逐字段比较 Node 参考用例
./gradlew.bat :app:testDebugUnitTest
```

重新导入图鉴的 `./build.ps1 -ImportData` 同时刷新计算资源。常规 APK 构建使用已生成资源，无需安装 Node 依赖。更新上游时须明确更新源码副本、提交号、形态映射和验证用例；不要自动追随线上最新版。

# Champions 伤害计算器

入口：侧边栏“伤害计算”，或宝可梦详情底部“用于伤害计算”。界面按设计稿 v2：攻击方、防守方两张卡片（点上半部分换宝可梦，点下半部分配置特性、道具、能力调整、能力点、能力等级与状态），下方是场地与招式两张摘要卡；结果吸附在底部（横屏时位于右侧），打开的二级菜单覆盖在结果之上。界面使用原生 Compose，计算规则为 Kotlin 原生代码；无需网络、网页服务或脚本解释器。

## 计算与数据边界

- 规则移植自邻目录 `damage-calc` 的 `calc/src`，固定提交 `eb9af6d94e7ee0ce034d2d6f2d44d4b2d66ff981`。副本在 `vendor/damage-calc/src`，源文件未修改。对应 `Generations.get(0)` 的 Champions 规则，固定 50 级、每项能力点 0–32；上游没有限制总能力点；能力点页的加减按钮按 Champions 规则限制每只合计 66 点；直接输入数字仍允许超出，用于假设分配，合计超出时以强调色提示。默认配置：攻击方按招式分类为固执/内敛、攻击或特攻 32 + 速度 32 + HP 2；防守方为淘气/温和、HP 32 + 对应防御 32 + 另一防御 2。
- 396 条形态通过明确规则与 `scripts/calculator/form-aliases.json` 映射。形态属性、种族值、体重取自 `dex.json`；特性限定为该形态的源数据。性别遵守源数据的固定性别。
- 335 个开放攻击招式可选。威力、分类、属性、优先度和接触标记使用图鉴字段；动态威力标记 1 保留上游规则。其余伤害相关标记和特殊效果取自上游。
- “拍击”存在于图鉴开放表，但缺少上游 Champions 记录。仅这一招显式取上游第九世代的通用招式元数据，仍按 Champions 规则计算，并使用图鉴数值。
- 道具范围采用上游 Champions 表的 166 项；中文名从与图鉴同指纹的 `champout/item.csv` 导入，并校验 manifest 哈希。不是从 Wiki 描述推测道具效果。
- 默认招式列表按当前形态学习关系过滤。“全部开放攻击招式”允许假设组合，并标出无法学习的招式。从列表选择新宝可梦重置该方配置；同一物种的形态切换保留能力调整（性格）、能力点、道具与条件，只更新特性与性别；交换保留双方配置并交换各方场地状态。
- 百变怪等没有开放攻击招式的形态可以正常进入和选择，显示无招式提示，不生成伤害结果。可手动开启全部招式后选择假设招式；关闭时恢复学习表约束，没有合法招式则清除结果。

可调项：能力调整（“提升 ×1.1”与“降低 ×0.9”两项独立选择；两项都选且不同时换算为对应性格名参与计算，否则按无修正计算并提示）、能力点、五项能力等级、特性及条件触发、道具、HP 百分比、异常状态、性别、倒下队友数、要害、合法多段命中次数、单双打、天气、场地、重力、奇妙/魔法空间、双方墙/守住/顺风/帮助/友情防守/充电。上游 Champions 规则不读取蓄电池、能量点、钢之意志与花之礼，界面不提供这些开关。

天气、场地在界面中明确指定，天气特性不会自动改写场地输入；威吓等入场能力修正遵循上游执行顺序。需要手动关闭或更换假设特性来模拟它未触发的情况。

## 结果含义

输出伤害范围、占最大 HP 的百分比、逐段随机伤害值，以及伤害达到当前 HP 的概率。单段按上游 16 个等概率随机值；多段逐段卷积，不能把每段第 i 个随机值直接相加后当作完整分布。

这些结果假定招式命中；不包含命中率、气势披带、挺住、回合末伤害/回复、换入钉子或完整回合模拟。连续使用招式的回合数固定为 1。概率是伤害阈值概率，不代表包含所有存活机制的击倒概率。上游已有规则和局限随该固定版本保留，未声明为 Champions 实机逐项校验结果。

## 实现和更新

性能：计算是纯 Kotlin，1238 个参考用例连同 JSON 解析在开发机 JVM 上合计约 0.4 秒，因此每次修改输入后在组合中直接得出结果，无防抖、无“正在计算”过渡，也没有启动预热。仅首次打开前需解析约 110 KB 的 `catalog.json`；图鉴列表显示后会在 IO 线程提前解析，未完成时结果区显示“正在载入计算数据”。

`DamageCalc.kt` 是上游 `mechanics/champions.ts`、`mechanics/util.ts` 及 `pokemon.ts`、`move.ts`、`field.ts`、`stats.ts`、`result.ts` 中 Champions 路径的逐行移植：算术用 `Double` 复现 JavaScript 数值（含 `pokeRound`、16/32 位溢出与 32 位截断的 `chainMods`），对象按上游顺序就地修改（包括亲子爱子代共享防守方、招式与场地），因此逐个随机值与原版一致。上游的已知怪癖也照搬，例如 Champions（第 0 代）速度上限按第 1–2 代取 999、多段命中时 `dropsStats` 读取防守方能力等级、`Lash Out` 永不加成。未移植只生成描述文本的 `rawDesc`，以及计算器不提供输入的太晶、极巨化、Z 招式与夸克充能/古代活性指定能力。

`CalculatorEngine.kt` 取代原 `adapter.js`：校验输入（报错文案不变）、把图鉴形态与招式映射为上游名称，再整理伤害范围、百分比、逐段随机值与阈值概率。引擎无状态、线程安全，按 `Dex` 与 `CalculatorCatalog` 在页面内创建。输入及列表状态通过现有 SaveableStateProvider 随栏目/返回栈条目保存。

`CalculatorData.kt` 集中默认配置、宝可梦/形态选择、学习表约束和双方交换规则，供界面及单元测试共用。`CalculatorCatalog` 将 `catalog.json` 解析为只读数据（性格、道具及其效果、多段命中范围、形态/招式/特性的上游名称、招式机制字段、属性相性表），在 ViewModel 内加载一次。图鉴的形态顺序、已开放招式和学习表索引由 `Dex` 统一建立；界面展示用的属性相性由 `TypeChart.kt` 提供，计算使用 `catalog.json` 中上游导出的相性表。请求 JSON 合同（页面保存的状态）不变。

`scripts/calculator/build.cjs` 用 TypeScript 在 Node 中加载上游源码（`upstream.cjs`），只导出数据：形态映射、每个开放招式的上游机制字段（基础威力、标记、多段、附加效果、反作用、目标等）、道具效果（属性强化、抗性树果、投掷威力、超级石对应）、性格与属性相性。类型、分类、优先度、接触与固定威力仍取图鉴。生成的 `catalog.json`、`provenance.json` 不手改；APK 中不再有 JavaScript。`provenance.json` 记录上游提交、逐文件源码哈希、图鉴/道具来源哈希及输出哈希；`build.ps1` 在构建前核对。没有邻目录 champout 时，导入仅在图鉴哈希与上次导入一致时复用已校验的道具中文名。

`scripts/calculator/test.cjs` 用上游源码加原 `adapter.js`（现仅作参考实现）生成 `fixtures.json`：38 个命名场景、1188 个固定种子组合（三轮遍历全部形态，使每个形态的每个特性都在攻防两侧出现，335 个开放攻击招式各出现多次，166 个道具攻防两侧轮换，并混入天气、场地、墙、能力等级、异常状态、要害、多段次数等条件）以及 12 个输入校验错误。`CalculatorEngineTest` 逐字段比较伤害、随机值、阈值概率与实数值。

```powershell
# 重建计算数据、映射、中文道具表和参考用例，再打包优化版
./build.ps1 -ImportCalculator
# 仅执行上游覆盖检查并刷新参考用例
node scripts/calculator/test.cjs
# Kotlin 原生计算逐例对照参考用例
./gradlew.bat :app:testDebugUnitTest
```

重新导入图鉴的 `./build.ps1 -ImportData` 同时刷新计算数据。常规 APK 构建与单元测试使用已生成资源，无需 Node。更新上游时须明确更新源码副本、提交号、形态映射和参考用例，并逐项检查 `mechanics/champions.ts` 与 `mechanics/util.ts` 的差异后同步到 `DamageCalc.kt`；参考用例不一致即说明移植未跟上。不要自动追随线上最新版。
